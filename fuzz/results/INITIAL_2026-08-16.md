# Initial Differential Fuzzing Campaign - 2026-08-16

## Question

Does coverage-guided input generation expose a byte-level `seal` discrepancy
or an `open` acceptance/plaintext discrepancy between PVC-RotSymEnc-1 and the
independent Candidate A1 implementation?

## Method

The two libFuzzer targets documented in `fuzz/README.md` were started from
empty writable corpora plus the checked-in seed corpora. The complete canonical
and independent call trees were built with coverage instrumentation, ASan and
UBSan. Each target ran with a fixed seed and a 4,096-byte maximum input length.

## Parameters

```text
Base revision:       b3c67bccb480fe9cdf091120049df1b2ceceb51b
Platform:            Linux x86-64
Compiler:            Debian Clang 19.1.7
Build type:          RelWithDebInfo
Instrumentation:     libFuzzer + ASan + UBSan
Seal seed:           1001
Seal executions:     4096
Seal seed corpus:    2 files, 192 bytes
Open seed:           2002
Open executions:     4096
Open seed corpus:    4 files, 514 bytes
Maximum input:       4096 bytes
```

LeakSanitizer was disabled because the managed execution environment runs
under `ptrace`, where LSan reported that it could not initialize. ASan and UBSan
remained active. This is an explicit coverage limitation, not a leak-clean
result.

## Result

```text
Seal: mismatches=0 sanitizer_findings=0 new_units=91  peak_rss_mb=54
Open: mismatches=0 sanitizer_findings=0 new_units=139 peak_rss_mb=55
```

The seal campaign averaged 163 executions/second. The open campaign averaged
141 executions/second. No crash artifact was produced.

## Interpretation

No wrapper/independent discrepancy was found within these two fixed-seed,
4,096-execution campaigns. The harnesses reached new coverage relative to the
checked-in seeds and exercised both raw rejection behavior and generated valid
open behavior.

## Limitations

- This campaign covers 8,192 total executions, not the planned million-scale
  campaign.
- Inputs were limited to 4,096 bytes.
- Only one compiler, platform and optimization profile were fuzzed.
- Leak detection was disabled due to the runner limitation.
- Canonical and independent A1 share the same frozen C1 implementation.
- No observed discrepancy is not evidence that C1, M1, A1 or RotSymEnc is
  cryptographically secure.

## Reproduction

Build the fuzz targets as documented in `fuzz/README.md`, then run from empty
writable corpora:

```bash
work="$(mktemp -d)"
mkdir -p "$work/seal" "$work/open" "$work/artifacts/seal" "$work/artifacts/open"

ASAN_OPTIONS=detect_leaks=0 \
./build-fuzz/pvc-rotsymenc1-fuzz-seal-equivalence \
  -seed=1001 -runs=4096 -max_len=4096 -verbosity=0 -print_final_stats=1 \
  -artifact_prefix="$work/artifacts/seal/" \
  "$work/seal" fuzz/corpus/seal-equivalence

ASAN_OPTIONS=detect_leaks=0 \
./build-fuzz/pvc-rotsymenc1-fuzz-open-equivalence \
  -seed=2002 -runs=4096 -max_len=4096 -verbosity=0 -print_final_stats=1 \
  -artifact_prefix="$work/artifacts/open/" \
  "$work/open" fuzz/corpus/open-equivalence
```
