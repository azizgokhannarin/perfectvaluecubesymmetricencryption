# Cross-Platform Conformance

## Status

This document pre-registers the remote platform campaign before its first run.
The candidate construction and canonical cryptographic vectors are unchanged.

## Question

Do supported compilers and operating systems produce byte-identical
PVC-RotSymEnc-1 seal/open behavior for the same deterministic inputs?

## Method

`pvc-rotsymenc1-cross-platform-conformance` generates a versioned binary
transcript. Every record contains the case index, tag size, both keys, nonce,
associated data, plaintext, ciphertext, tag, successfully opened plaintext,
and the rejection status for a one-byte tag mutation. Integers in the
transcript use explicit unsigned 64-bit big-endian encoding.

The test driver computes SHA-256 over the complete transcript and compares it
with `test-vectors/cross-platform-conformance-v1.json`. SHA-256 is used only as
an external test fingerprint. It is not linked into or used by the candidate
construction.

Each platform must also pass the existing CTest suite, including official
vectors, tamper rejection, and canonical-wrapper-to-A1 equivalence. A matching
fingerprint is conformance evidence, not a cryptographic security result.

## Parameters

The remote campaign is fixed before observing any non-local platform result:

```text
transcript version = 1
seed = 0x43524F5353504C31
cases = 4096
tag profiles = 128, 192, and 256 bits, selected by case index
AD lengths = boundary schedule plus deterministic values in [0, 128]
plaintext lengths = boundary schedule plus deterministic values in [0, 256]
long plaintexts = 1024 and 4096 bytes at fixed intervals
AD/plaintext families = all-zero, all-one, sequential, alternating, random
```

The pre-registered platform matrix is:

| Platform | GitHub runner | Compiler |
|---|---|---|
| Linux ARM64 | `ubuntu-24.04-arm` | GCC |
| macOS ARM64 | `macos-15` | Apple Clang |
| Windows x64 | `windows-2025` | MSVC |
| Windows x64 | `windows-2025` | clang-cl |

These are standard hosted-runner labels listed in the
[GitHub-hosted runners reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners)
as observed on 2026-08-16. The local Linux x86-64 GCC 14.2 and Clang 19.1 builds
serve as preflight controls.

Before the remote campaign, both local controls generated byte-identical
transcripts with the following fixed reference values:

```text
transcript bytes = 2533365
SHA-256 = 42c2f89ac1e55d260cf8e90914f01e7fbcd39f54a50c814147bb1e5cc344ad8e
```

## Acceptance Criteria

- warnings-as-errors build succeeds;
- all existing CTest cases pass;
- the transcript size matches the pre-registered value;
- the transcript SHA-256 matches the pre-registered value;
- no construction source or existing canonical vector changes.

A mismatch must be retained and investigated. The expected fingerprint must not
be regenerated solely to make a platform pass.

## Limitations

- The matrix does not cover big-endian, 32-bit, embedded, or unusual C++
  standard-library implementations.
- Agreement among these implementations cannot prove absence of undefined
  behavior or establish cryptographic security.
- The canonical wrapper and frozen A1 path share the same C1 dependency.
- SHA-256 compresses the transcript for comparison; the complete generated
  transcript is not committed.

## Reproduction

```bash
cmake -S . -B build-conformance -DCMAKE_BUILD_TYPE=Release
cmake --build build-conformance \
  --target pvc-rotsymenc1-cross-platform-conformance --parallel 2
python3 scripts/verify_cross_platform_conformance.py \
  --generator build-conformance/pvc-rotsymenc1-cross-platform-conformance
```
